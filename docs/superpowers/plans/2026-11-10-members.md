# Members (directory + my profile) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or
> superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Active members get a paginated, searchable member directory and can edit their own profile (location, bikes,
Instagram, visibility, photo consent); names are tidied consistently and locked for members.

**Architecture:** Two new tables (`member_details`, private; `member_motorcycles`) beside `profiles`; other members'
data is only reachable through two security-definer RPCs (`member_directory`, `member_directory_counts`). A pure SQL
function `private.tidy_name` runs in BEFORE triggers on `applications` and `profiles`. A fill helper copies birth date,
Instagram, photo consent and the first bike from the approved application. Next.js pages `/members` and `/account`
read via `src/lib/members/queries.ts` and write via Server Actions in `src/lib/members/actions.ts`.

**Tech Stack:** Supabase Postgres 17 (declarative schemas, RLS, pgTAP), Next.js 16 App Router (Cache Components),
next-intl, Zod 4, shadcn/ui `base-nova` (Base UI), `node --test`.

**Spec:** `docs/superpowers/specs/2026-11-10-members-design.md` — read it first; this plan argues from it.

## Global Constraints

- Branch `feat/members` from `main`; Conventional Commits; author `iltan <iltancanerr@gmail.com>`; **no
  `Co-Authored-By` or any attribution trailer**. No worktrees.
- DB workflow per DB task: edit `supabase/schemas/*.sql` → `pnpm db:migration <name>` → review the generated file →
  `pnpm db:reset` → `pnpm db:test` → `pnpm db:types` → commit schema + migration + types together. DML is hand-written.
- Every table: RLS enabled **and** `revoke all … from anon, authenticated` + explicit (column) grants.
- Security-definer functions: `set search_path = ''`, fully qualified names, `revoke all … from public, anon`, grant
  execute only where needed. Policies use `(select auth.uid())`, `(select private.…())`.
- pgTAP tests are written **before** the SQL, use fixture ids `00000000-0000-0000-0000-0000000001xx` (unique to this
  iteration), scope every query to fixture ids (DB may hold real data), and include the must-fail cases.
- Insert only granted columns in tests (learnings: "Column grants also apply to `id` in inserts").
- Turkish collation name: `"tr-x-icu"` (verified locally: sorts `Cem, Çelik, Ilgın, Işık, İlker, Oğuz, Ömer, …`).
- `lower('İ')` in the DB yields `i̇` (with combining dot): always `translate()` Turkish i-letters before
  `upper()`/`lower()`.
- No hard-coded UI strings: keys in `messages/tr.json` (source of truth) and `messages/en.json`.
- Links/redirects from `@/i18n/navigation`; request-time data behind `<Suspense>`; never CSS-`uppercase` brand/English
  words on Turkish pages.
- Every list paginates (keyset, visible total). Page size: `PAGE_SIZE` (25) from `src/lib/pagination.ts`.
- Never log personal data; log only error codes.
- Before every code commit: `pnpm lint && pnpm exec tsc --noEmit && pnpm test` (+ `pnpm db:test` for DB tasks);
  `pnpm build` at least in Tasks 9, 10 and 12.
- Learnings (`docs/learnings/*.md`, entry format in its README) and `docs/follow-ups.md` are updated in the same commit
  as the work that discovers / defers something.

## Review Focus

1. **Search typed without Turkish letters or in the "wrong" case** — `celik`, `ilker`, `IŞIK` must find `Çelik`,
   `İlker`, `Işık` (plain `ilike` fails on `İ/ı`). Pinned in Task 5 (`private.search_fold`).
2. **Search containing `%`, `_` or `\`** — treated literally, not as wildcards. Pinned in Task 5.
3. **Members without district or without bikes** (manually activated, other city, "no motorcycle") — card shows no
   stray "·", no empty bike block; they still count in the total but in neither side chip. Pinned in Tasks 5 and 7.
4. **Instagram typed as `@handle`, `instagram.com/handle`, or a full URL with trailing `/` or `?igsh=…`** — stored as
   `handle`; anything else is "invalid". Pinned in Task 8.
5. **"Show my birthday" when no birth date is stored** (manually activated member) — directory shows nothing; profile
   shows the toggle disabled with a hint. Pinned in Tasks 5 and 12.
