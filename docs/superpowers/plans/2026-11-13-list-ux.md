# List UX (instant filtering, clean URLs, page numbers) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or
> superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `/members` and `/admin/members` load their whole list once (up to 2,000 rows, failing loudly above) and
search / filter / page in the browser with clean URLs; `/admin/applications` gets numbered offset pages; all three share
a new numbered pager.

**Architecture:** Pure, dependency-free helpers (`src/lib/pagination.ts`, `src/lib/search-fold.ts`, `src/lib/list-url.ts`)
carry the logic and the unit tests. The server reads all rows in 1,000-row `.range()` chunks (`readAll`) under RLS and
hands them to a client list component, which keeps `q` / chip / `page` in the URL through the native History API
(`replaceState` while typing, `pushState` for chips and pages). `/admin/applications` stays a server list with
`?page=N` and `.range()` + `count: "exact"`. One `src/components/pager.tsx` renders the numbered pager as buttons
(client) or links (server).

**Tech Stack:** Next.js 16 App Router (Cache Components, React Compiler), next-intl 4, Supabase (PostgREST, pgTAP,
declarative schemas), shadcn/ui `base-nova`, `node --test`, puppeteer E2E (`scripts/e2e/`).

**Spec:** `docs/superpowers/specs/2026-11-13-list-ux-design.md` — read it first; this plan argues from it.

## Review Focus

1. **Back / forward after typing and chip taps** — type "ali", tap "Anadolu", tap page 2, press back twice: the list,
   the chip, the page **and the search box text** follow the URL each time. Pinned in Task 2 (hook test of the
   URL→state sync helper) and Task 6 (E2E).
2. **No server round trip on search / chip / page** — under Cache Components and `partialPrefetching`, a `pushState`
   with a new search string must not trigger an RSC fetch or the Suspense skeleton. Pinned in Task 6 (E2E counts
   requests whose URL contains `_rsc` or `RSC: 1` while typing/tapping: 0).
3. **Safety filter after an in-browser search** — type "çel", tap "Avrupa", then pick a blood type: the server
   navigation keeps `q=çel&side=european`, and the result is filtered by both. Pinned in Task 3 (component reads
   `useSearchParams`) and Task 6 (E2E).
4. **Admin action that empties the current page** — on `/admin/members?status=pending&page=2` with 26 pending,
   activating the last pending row: after `refresh()` the URL is clamped to page 1 and the row is gone from the list,
   counts updated. Pinned in Task 2 (`clampPage`) and Task 6 (E2E).
5. **Hostile or odd `?page=`** — `page=0`, `-3`, `2.5`, `1e3`, `abc`, `99` (past the end), repeated `page=2&page=3`:
   never a crash, never an empty page with results available; client corrects the URL, server
   (`/admin/applications`) redirects to the clamped page. Pinned in Task 1 (`parsePage`/`clampPage` cases) and Task 5.

**Interfaces — Produces** (all dependency-free, relative `.ts` imports in tests):
- `pagination.ts` (keep existing exports for now; dead ones go in Tasks 3–5):
  - `export const LIST_CEILING = 2000; export const CHUNK_SIZE = 1000;` (`PAGE_SIZE = 25` stays)
  - `parsePage(value: unknown): number` — 1-based; anything but a canonical positive integer string (`/^[1-9]\d{0,5}$/`)
    → 1; arrays → 1.
  - `pageCount(total: number, size?: number): number` — `max(1, ceil(total / size))`.
  - `clampPage(page: number, total: number, size?: number): number` — into `[1, pageCount]`.
  - `pageItems(current: number, count: number): (number | "gap")[]` — first, last, current ±1; a gap only when it
    hides ≥ 2 pages (a single hidden page is shown as its number).
  - `readAll<T>(fetchRange: (from: number, to: number) => Promise<T[]>, ceiling?: number, chunk?: number):
    Promise<{ items: T[]; overCeiling: boolean }>` — calls `fetchRange(0, chunk-1)`, `(chunk, 2*chunk-1)`, … until a
    chunk returns fewer than `chunk` rows or more than `ceiling` rows are in hand; returns at most `ceiling` items and
    `overCeiling = rowsSeen > ceiling`. Never requests past index `ceiling` (last range ends at `ceiling`, i.e. asks
    for ceiling + 1 rows in total).
- `search-fold.ts`: `foldSearch(value: string): string`; `normalizeQuery(value: string | null | undefined): string`
  (trim, slice to 60 code points); `matchesFolded(foldedHaystack: string, foldedQuery: string): boolean` (empty
  query matches everything).
- `list-url.ts`: `listSearch(values: Record<string, string | number | null | undefined>, defaults:
  Record<string, string | number>): string` — returns `""` or `"?k=v&…"`, keys in the given order, dropping empty,
  null/undefined and default-equal values; `URLSearchParams` encoding.

test("parsePage accepts canonical positive integers only", () => {

  assert.equal(pageCount(0), 1); assert.equal(pageCount(25), 1); assert.equal(pageCount(26), 2);
  assert.equal(clampPage(99, 148), 6); assert.equal(clampPage(0, 148), 1); assert.equal(clampPage(3, 0), 1);

test("readAll reads chunks until a short one and flags the ceiling", async () => {
  const source = (n: number) => { const calls: [number, number][] = [];
    return { calls, fetch: async (from: number, to: number) => { calls.push([from, to]);
      return Array.from({ length: Math.max(0, Math.min(to, n - 1) - from + 1) }, (_, i) => from + i); } }; };
  for (const [n, items, over, calls] of [[150, 150, false, 1], [1000, 1000, false, 2], [2000, 2000, false, 3],
    [2001, 2000, true, 3], [5000, 2000, true, 3]] as const) {
    const s = source(n); const r = await readAll(s.fetch, 2000, 1000);
    assert.equal(r.items.length, items); assert.equal(r.overCeiling, over); assert.equal(s.calls.length, calls);
    assert.ok(s.calls.every(([, to]) => to <= 2000), "never asks past ceiling + 1 rows");
  }
