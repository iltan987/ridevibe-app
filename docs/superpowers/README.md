# Design specs and implementation plans (archive)

`specs/` and `plans/` hold one design spec and one implementation plan per iteration, written by the superpowers
`brainstorming` and `writing-plans` skills; new ones land here too (add a row below). They are **history**: each
records what was decided and planned on its date. On any conflict the live docs win: `CLAUDE.md` (rules),
`docs/PLAN.md` (decisions, status), `docs/learnings/`, `docs/application-form.md`, and the code. Read a spec for the
*why* behind a feature; don't copy its details (names, signatures, steps) without checking the code.

"Later changes" lists the main verified ways the current state differs from a spec/plan and where that is recorded now
(not exhaustive). "Built:" marks a difference that already came in during the iteration itself.
